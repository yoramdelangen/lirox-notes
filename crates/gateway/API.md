# LiroxNotes Gateway API

This is the authoritative API reference for the Actix gateway. It is written
as a flat, explicit endpoint catalogue so it can be read by humans or used as
context by an AI system.

## Connection

- Base URL: `http://127.0.0.1:3010`
- JSON endpoints use `Content-Type: application/json`.
- Note body endpoints accept the request body as raw text. `text/markdown` is
  recommended.
- The server binds to `127.0.0.1` only. The port defaults to `3010`.
- API responses receive development CORS headers in debug builds, or when
  `LIROX_DEV_CORS` is set. Allowed origin is `http://localhost:8989` and
  credentials are allowed.

## Authentication

Login creates one server-side session stored in the configured session file.
Send its cookie on protected requests:

```http
Cookie: lirox_session=<token>
```

The cookie is `HttpOnly`, `SameSite=Lax`, and scoped to `/`. A missing or
invalid cookie returns:

```json
{"error":"login required"}
```

with status `401`. Authentication is intentionally local: passwordless users
only need the matching username; password users also need the matching
password.

## Common Errors

JSON API errors use this shape unless an endpoint explicitly says otherwise:

```json
{"error":"<message>"}
```

Common statuses:

| Status | Meaning |
|---|---|
| `400` | Workspace is not configured, invalid note path, or application is not installed |
| `401` | Login cookie is missing or invalid, or credentials are invalid |
| `404` | Workspace or repository identifier does not match the configured one |
| `500` | Filesystem, Git, or configuration failure; response is generated by Actix |

Protected endpoints generally check authentication before workspace
configuration. `GET /api/workspace/{path}` and `PUT /api/notes/{path}` return
the `400` error as plain text (`workspace is not configured`) when no workspace
exists, rather than the JSON error object.

## Authentication And Setup

### `GET /api/auth`

Returns the current session state. It does not require authentication and does
not reject an invalid cookie; invalid or absent cookies are reported as an
unauthenticated session.

Response: `200` with `SessionResponse`.

### `GET /api/auth/{path}`

Wildcard alias for the auth status endpoint. The `{path}` value is ignored.
For example, `/api/auth/session` returns the same response as `/api/auth`.

Response: `200` with `SessionResponse`.

### `POST /api/auth/login`

Validates credentials, creates a session, persists it server-side, and returns
the session cookie.

Request body: JSON `LoginRequest`.

| Field | Type | Required | Behavior |
|---|---|---:|---|
| `user` | string | No | Defaults to `local` when absent or blank |
| `password` | string | No | Defaults to an empty string |

Success: `200`, `SessionResponse`, and `Set-Cookie`.

Failure: `401` JSON `{"error":"invalid username or password"}`.

### `POST /api/auth/logout`

Deletes the server-side session and clears the `lirox_session` cookie. It does
not require a valid session.

Success: `200` with an unauthenticated `SessionResponse` and
`Set-Cookie: lirox_session=...; Max-Age=0`.

### `POST /api/setup`

Initializes installation state and the local user, then signs that user in.
This endpoint does not create the workspace configuration; call
`POST /api/workspaces` afterward.

Request body: JSON `InstallRequest`.

| Field | Type | Required | Default |
|---|---|---:|---|
| `workspace_root` | string | No | Configured default workspace root |
| `user` | string | No | `local` |
| `auth_mode` | string | No | `passwordless`; only exact `password` enables password auth |
| `password` | string | No | Empty string; required when `auth_mode` is `password` |

Success: `201`, `SessionResponse`, and a session cookie.

Failure: invalid user/password or filesystem errors may produce `500`.

## Workspaces

### `GET /api/workspaces`

Lists configured workspaces. The current implementation returns an array with
zero or one item, not a multi-workspace store.

Requirements: valid session and configured workspace.

Success: `200` with `WorkspaceResponse[]`.

Failure: `400` JSON `workspace is not configured`.

### `POST /api/workspaces`

Creates or replaces the configured workspace profile. It creates a local Git
workspace, or clones a remote repository when `repo_mode` is `remote`.

Authentication: required after installation has already configured a
workspace; allowed without login during first workspace setup.

Request body: JSON `WorkspaceRequest`.

| Field | Type | Required | Behavior |
|---|---|---:|---|
| `repo_mode` | string | No | Only `remote` uses `repo_url`; other values create a local workspace |
| `workspace_slug` | string | No | Slugified; defaults to the repo name or `workspace` |
| `workspace_name` | string | No | Defaults to `My Workspace` |
| `repo_url` | string | No | Remote URL when `repo_mode` is `remote`; otherwise cleared |
| `branch` | string | No | Defaults to `main` |

The workspace path is derived from the installed workspace root and the slug.

Success: `201` with `WorkspaceResponse`.

Failures: `400` `application is not installed`; `401` when authentication is
required; Git/filesystem failures may produce `500`.

### `GET /api/workspaces/{workspace}`

Returns the configured workspace summary.

Requirements: valid session and configured workspace. `{workspace}` must equal
the configured workspace slug.

Success: `200` with `WorkspaceResponse`.

Failures: `400` `workspace is not configured`; `404` JSON
`workspace not found`.

### `POST /api/workspaces/{workspace}/sync`

Synchronizes a workspace. Remote workspaces are pulled with Git fast-forward
only; local workspaces are left unchanged.

Requirements: valid session, configured workspace, and matching `{workspace}`.

Success: `200` with `SyncResponse`. For a local workspace, `pulled` and
`pushed` are `false` and `message` is `local workspace has no remote`. For a
remote workspace, `pulled` is `true`, `pushed` is `false`, and `message` is
`pulled`.

### `POST /api/workspaces/{workspace}/pull`

Pulls from `origin/{branch}` using `git pull --ff-only`.

Requirements: valid session, configured workspace, and matching `{workspace}`.

Success: `200` with `SyncResponse`. `pulled` is `true` for a remote workspace,
otherwise `false`; `pushed` is always `false`.

### `POST /api/workspaces/{workspace}/push`

Pushes the current branch to `origin/{branch}`.

Requirements: valid session, configured workspace, and matching `{workspace}`.

Success: `200` with `SyncResponse`. `pushed` is `true` for a remote workspace,
otherwise `false`; `pulled` is always `false`.

## Workspace Files And Notes

### Path requirements for file and note endpoints

The path must:

- Be non-empty.
- End with `.md`.
- Be relative, not absolute.
- Contain only normal path components.
- Not contain `..`, `.`, or platform root/prefix components.

Invalid paths return `400` JSON `invalid note path` for workspace file routes,
or plain text `invalid note path` for `/api/notes/{path}`.

### `GET /api/workspaces/{workspace}/files/{path}`

Reads a Markdown file from the configured workspace.

Requirements: valid session, configured workspace, matching workspace slug,
and valid note path.

Success: `200` with `FileResponse`. A missing file is a filesystem failure and
may produce `500`.

### `PUT /api/workspaces/{workspace}/files/{path}`

Writes the raw request body to a Markdown file. Parent directories are created
as needed. The change is committed locally to Git; it is not pushed remotely.

Requirements: valid session, configured workspace, matching workspace slug,
valid note path, and a text request body.

Success: `200` with `SaveResponse`.

### `DELETE /api/workspaces/{workspace}/files/{path}`

Deletes a Markdown file and commits the deletion locally. Deleting an already
missing file is successful but reports `committed: false`.

Requirements: valid session, configured workspace, matching workspace slug,
and valid note path.

Success: `200` with `SaveResponse`.

### `PUT /api/notes/{path}`

Legacy workspace-scoped equivalent of the file save endpoint. It uses the
configured workspace without requiring a workspace slug in the URL, writes the
raw body, and creates a local Git commit. It never pushes.

Requirements: valid session, configured workspace, valid Markdown path, and a
text request body.

Success: `200` with `SaveResponse`.

Failures: `400` plain text for missing workspace or invalid path.

### `GET /api/workspace/{path}`

Returns the complete workspace view used by the UI. An empty `{path}` selects
`notes/welcome.md`; an unknown selected path falls back to the first available
note or the default note path.

Requirements: valid session and configured workspace.

Success: `200` with `WorkspaceView`.

Failure: `400` plain text `workspace is not configured`.

## Conflicts And Trash

### `GET /api/workspaces/{workspace}/conflicts`

Returns the workspace conflict list. The current implementation always returns
an empty list.

Requirements: valid session, configured workspace, and matching workspace slug.

Success: `200` with `{ "items": [] }`.

### `GET /api/workspaces/{workspace}/trash`

Returns the workspace trash list. The current implementation always returns an
empty list.

Requirements: valid session, configured workspace, and matching workspace slug.

Success: `200` with `{ "items": [] }`.

## Repositories

Repository IDs are currently the same as the configured workspace slug. Only
one configured repository is returned.

### `GET /api/repositories`

Lists the configured repository.

Requirements: valid session and configured workspace.

Success: `200` with `RepositoryResponse[]`.

### `GET /api/repositories/{repo_id}`

Returns the configured repository summary.

Requirements: valid session, configured workspace, and matching `{repo_id}`.

Success: `200` with `RepositoryResponse`.

Failure: `404` JSON `repository not found` for an unknown ID.

### `POST /api/repositories/{repo_id}/connect`

Configures Git remote `origin`, saves the repository URL and branch, and
returns the updated summary. Existing `origin` is updated; otherwise it is
added.

Requirements: valid session, configured workspace, and matching `{repo_id}`.

Request body: JSON `RepositoryRequest`.

| Field | Type | Required | Behavior |
|---|---|---:|---|
| `repo_url` | string | Yes | New remote URL; empty values are accepted by the handler |
| `branch` | string | No | Replaces the branch when non-blank; otherwise keeps the current branch |

Success: `200` with `RepositoryResponse`.

### `POST /api/repositories/{repo_id}/disconnect`

Attempts to remove Git remote `origin`, clears the saved repository URL, and
keeps the configured branch.

Requirements: valid session, configured workspace, and matching `{repo_id}`.

Success: `200` with `RepositoryResponse` where `connected` is `false`.

### `OPTIONS /api/{path}`

Generic API CORS preflight handler. It accepts any API path covered by the
catch-all route.

Success: `204` with no body and development CORS headers when CORS is enabled.

### `OPTIONS /api/workspaces/{workspace}/files/{path}`

There is no dedicated route registration for this path. It is handled by the
generic `OPTIONS /api/{path}` route above.

### `OPTIONS /api/repositories/{repo_id}/connect`

There is no dedicated route registration for this path. It is handled by the
generic `OPTIONS /api/{path}` route above.

### `OPTIONS /api/notes/{path}`

Dedicated note-save preflight handler.

Success: `204` with no body and development CORS headers when CORS is enabled.

### `OPTIONS /api/workspace/{path}`

Dedicated workspace-view preflight handler.

Success: `204` with no body and development CORS headers when CORS is enabled.

## Response Schemas

### `SessionResponse`

```json
{
  "installed": true,
  "authenticated": true,
  "user": "local",
  "auth_mode": "passwordless",
  "workspace_required": false,
  "workspace_root": ".lirox-runtime/workspace"
}
```

Fields: `installed` and `authenticated` are booleans; `user`, `auth_mode`,
and `workspace_root` are strings; `workspace_required` is true when no
workspace configuration exists.

### `WorkspaceResponse`

```json
{
  "slug": "demo",
  "name": "My Workspace",
  "path": ".lirox-runtime/workspace/demo",
  "branch": "main",
  "source": "local git",
  "note_count": 1,
  "changed_notes": 0
}
```

### `WorkspaceView`

```json
{
  "slug": "demo",
  "name": "My Workspace",
  "branch": "main",
  "source": "local git",
  "note_count": 1,
  "changed_notes": 0,
  "unpushed_commits": 0,
  "selected_note": {
    "path": "notes/welcome.md",
    "title": "Welcome",
    "labels": [],
    "links": [],
    "active": true
  },
  "selected_note_body": "# Welcome",
  "tree": [],
  "labels": [],
  "notes": []
}
```

`selected_note` and each item in `notes` are `NoteSummary` objects. Each
`NoteSummary` has string `path`, string `title`, string arrays `labels` and
`links`, and boolean `active`. `tree` contains `TreeEntry` objects with
`kind` (`Folder` or `File`), `label`, `path`, numeric `depth`, and boolean
`active`. `labels` contains `{name, count}` objects.

### `FileResponse`

```json
{"path":"notes/manual.md","body":"# Manual note\n"}
```

### `SaveResponse`

```json
{"ok":true,"committed":true,"pushed":false}
```

`committed` reports whether a local Git commit was created. Save and delete
operations never push, so `pushed` is always `false`.

### `SyncResponse`

```json
{"ok":true,"pulled":true,"pushed":false,"message":"pulled"}
```

### `RepositoryResponse`

```json
{
  "id":"demo",
  "repo_url":"git@example.com:me/notes.git",
  "branch":"main",
  "connected":true
}
```

## Minimal Request Examples

```http
### Check session
GET {{host}}/api/auth

### Login
POST {{host}}/api/auth/login
Content-Type: application/json

{"user":"local","password":""}

### Create a local workspace
POST {{host}}/api/workspaces
Content-Type: application/json
Cookie: lirox_session={{session}}

{"workspace_slug":"demo","workspace_name":"Demo","repo_mode":"local","branch":"main"}

### Read a note
GET {{host}}/api/workspaces/demo/files/notes/welcome.md
Cookie: lirox_session={{session}}

### Save a note
PUT {{host}}/api/workspaces/demo/files/notes/manual.md
Content-Type: text/markdown
Cookie: lirox_session={{session}}

# API note
```
